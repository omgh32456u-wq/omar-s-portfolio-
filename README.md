# Builder’s Portfolio

Build a complete, polished, production-ready personal portfolio website for an Egyptian student, developer, and AI builder. This is a real portfolio, not a generic link-in-bio page.

IDENTITY AND CONTENT
- Present the owner honestly as a student, developer, and AI builder. Do not invent a full name, job title beyond that, years of experience, client count, project count, awards, testimonials, employers, or results.
- Use editable placeholders only where essential personal details are unknown (name, short bio, email, social URLs). Make them easy to replace in one central content/config file.
- Feature two real projects with accurate status:
  1. Mizano — a nutrition tracking app in development. It is intended to track meals, calories, protein and macros, with progress and food-management screens. Do not claim unfinished AI, authentication, reminders, rewards, or donation features are live.
  2. KingdomForge — an early-stage 3D medieval strategy game concept/prototype for Android, focused on interconnected kingdom, economy, building, citizens, and military systems. Do not present it as a finished or published game.
- Do not fabricate screenshots, download files, live demos, or links. If project visuals are needed, create tasteful original abstract mockups clearly presented as concept visuals, not real screenshots.
- Include About, selected projects, skills/tools, and contact sections. Keep copy concise, confident, and specific without inflated claims.

ART DIRECTION
- Premium, distinctive developer/AI-builder aesthetic: deep charcoal/midnight background (around #171923), layered surfaces (#252938), muted teal (#38C6B0), soft violet (#A77BFA), and warm off-white text (#F0F0F5).
- Avoid a flat pure-black background. Use subtle technical grid lines, connection paths, nodes, blueprint/code annotations, restrained gradients, soft shadows, and tasteful glass surfaces. Keep it sophisticated, not cyberpunk, not noisy, not template-like.
- Strong typography, clear hierarchy, generous spacing, refined cards, polished navigation, and excellent mobile responsiveness.
- Build a memorable hero section that communicates student + developer + AI builder, with a distinctive visual composition and clear CTA to projects/contact.
- Add a hamburger mobile nav, dark/light theme toggle, horizontal social icon row with editable placeholder links, smooth section navigation, and subtle cursor/hover feedback where appropriate.
- Add tasteful motion and scroll reveals, but prioritize performance and reduced-motion accessibility. Do not add heavy 3D scenes, autoplay video, or expensive external APIs in this first build.
- Contact should use a functional mailto link with a placeholder email, not a fake backend form.
- Persistent, clear links/CTAs; no dead buttons or invented download links.

IMPLEMENTATION
- Build the complete site now, not just a hero or mockup. Use the default Lovable stack and clean reusable components.
- Keep all personal content and links in one easy-to-edit data/config file.
- Ensure no horizontal overflow, accessible contrast, keyboard focus states, semantic structure, and responsive layouts.
- Run the available checks/build and fix errors before finishing.
- Do not add paid services, subscriptions, API keys, backend dependencies, or features that require ongoing costs.
- Prioritize a coherent finished baseline that can later be synced to GitHub and deployed to Vercel.
